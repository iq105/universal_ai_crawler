# 万能爬虫框架（Universal Crawler）实施计划

## Context

从零构建一个基于 LangChain/LangGraph 的万能爬虫框架：带操作界面，能智能解析分析各类网页，自动化处理不了的场景可转人工介入。

用户已确认的关键决策：
- **LLM**：OpenAI 兼容 API（base_url/api_key 环境变量配置，可接 DeepSeek/通义等）
- **存储**：PostgreSQL（任务/结果/日志 + LangGraph checkpointer 断点续跑）+ Redis（状态缓存）
- **功能**：任务管理与状态面板、智能页面解析、自动翻页与列表爬取、人工介入机制、数据预览与导出（首版全包含）
- **前端**：对话式 + 任务面板结合，风格类似 qoder/workbuddy

遵循用户历史项目约定：复杂多步逻辑用 LangGraph、人工介入用 interrupt 机制、原生 AsyncPostgresSaver checkpointer（thread_id=task_id）、事件经 SSE 推送（assistant_delta/assistant_reasoning/tool_start/tool_result/task_status/task_progress/items_batch/interrupt/done/error）、前端展示可折叠推理 + 自动展开工具卡片、保持代码简单可维护。

## 架构总览

- **爬虫全流程用单个 LangGraph 图**（多步、有中断、有循环），不做多 Agent 编排。图内"思考"节点（意图理解/方案生成/验证）调 LLM，"执行"节点（打开页面/提取/翻页/存储）直接调工具函数，不经 LLM 工具选择——爬取是确定性流程，保持可控。
- **事件推送**：每个节点/工具通过运行时传入的 `RunEventBus`（asyncio.Queue）主动推事件，API 层转发 SSE。
- **人工介入单点化**：所有介入收敛到唯一节点 `human_intervene`，用 state 的 `intervene_reason` 区分场景。resume 用 `Command(resume=value)`（若多断点残留，按历史经验从快照收集 pending interrupt ids 映射）。
- **双模式提取**：选择器模式（LLM 生成 CSS 选择器）+ LLM 结构化提取兜底（动态页/复杂结构），提取为空自动降级。

## LangGraph 图设计（crawler_graph.py）

**State（TypedDict, total=False）**：`task_id, url, instruction, status, page_snapshot, simplified_html, needs_login, dynamic_page, parse_scheme, items, page_no, max_pages, extract_fail_count, intervene_reason, human_guidance, error`

**节点与路由（9 节点）**：

| 节点 | 职责 | 出口边 |
|---|---|---|
| `intent_understand` | LLM 结构化理解：页类型/期望字段/需登录 | 需登录且无凭据 → human_intervene；否则 → page_load |
| `page_load` | Playwright 打开页面 + 快照 + 登录墙/验证码/反爬判定 | 命中 → human_intervene；成功 → page_analyze |
| `page_analyze` | LLM 分析：有无列表结构/重复块/分页类型/是否动态渲染 | 无法识别 → human_intervene；单页 → data_extract；列表 → scheme_generate |
| `scheme_generate` | LLM 生成 parse_scheme（字段 + 容器/条目选择器 + 翻页策略） | → data_extract |
| `data_extract` | 选择器模式（evaluate_js 批量取）/ LLM 模式兜底 | 空且计数<2 → scheme_generate；≥2 → human_intervene；有数据 → pagination |
| `pagination` | 按 mode 翻页：next 点击 / 加载更多 / 无限滚动 | 有下一页且 page_no<MAX_PAGES → data_extract；否则 → data_validate |
| `data_validate` | LLM 校验字段齐全/去重 | 通过 → store；失败1次 → scheme_generate；再失败 → human_intervene |
| `human_intervene` | **唯一 interrupt 节点**，`interrupt({reason, 快照, 截图, options})` | resume 后按 reason+guidance 路由到 page_load/scheme_generate/store/END |
| `store` | 批量写 crawl_results、任务置 success | → END |

**编译要点**：`StateGraph(CrawlerState)` + `AsyncPostgresSaver`；`graph.astream(init, config={"configurable":{"thread_id": task_id}}, stream_mode="updates")`，事件经 RunEventBus 转发。循环上限：extract/validate 失败重生成最多 2 轮。

## 工具集（ToolRegistry 注册）

- **browser_tools.py**：`open_page`、`get_page_snapshot`、`get_simplified_html`、`scroll_page`、`click_element`、`evaluate_js`（提取核心）、`fill_input`、`screenshot`
- **parse_tools.py**：`extract_by_scheme`（选择器批量提取）、`llm_extract`（JSON mode 结构化提取兜底）
- **storage_tools.py**：`save_items`（批量入库 + items_batch 事件）、`get_task`
- 所有工具经 ToolRegistry 注册，统一 audit 写 task_logs + 推 tool_start/tool_result 事件

## 智能解析核心算法

1. **结构识别**（page_analyze）：LLM 读可见文本快照，输出 `{has_list, item_blocks, pagination:{mode}, dynamic_rendered, sample_items}`
2. **方案生成**（scheme_generate）：LLM 基于精简 DOM 输出字段名 + 容器/条目选择器 + 字段取值方式（text/attribute href/image src/嵌套 selector）
3. **执行与降级**：`extract_by_scheme` 跑选择器；返回空/字段缺失 → 自动降级 `llm_extract`（传 DOM 批取 10 条）→ 成功则把第一条作为模板固化
4. **静态 vs 动态**：检测到 SPA/__NEXT_DATA__/容器有内容但快照为空 → 动态，强制 LLM 模式或滚动触底重取
5. **翻页策略**：next_button（click_element）/ load_more（click）/ infinite_scroll（循环 scroll_page），每页 page_no+1

## 人工介入流程

触发条件：登录墙/401/403 无凭据、验证码/滑块、反爬拦截、解析失败（无结构/提取空≥2/验证失败2次）、用户主动中断。

1. 图走到 `human_intervene` 调 `interrupt()` 暂停，checkpointer 持久化
2. 后端检测 updates 中 `__interrupt__` → 推 interrupt 事件 → 任务状态置 waiting_interrupt（DB+Redis）
3. 前端 InterruptDialog 弹出：原因 + 截图 + 快捷选项 + 自由文本框
4. 用户提交 → POST /resume → 取快照构造 `Command(resume=value)` → astream(None) 恢复 → SSE 恢复推送
5. resume 后按 `intervene_reason` + `human_guidance` 条件路由到对应节点继续

## 数据库表（PostgreSQL）

- **crawl_tasks**：id(UUID PK=thread_id), url, instruction, status, progress, parse_scheme(JSONB), total_items, error, created_at/updated_at
- **crawl_results**：id(BIGSERIAL), task_id(FK, 索引), item_index, page_no, data(JSONB), created_at
- **task_logs**：id, task_id(FK, 索引), level, source, message, created_at
- checkpointer 表由 `AsyncPostgresSaver.setup()` 自动创建
- Redis：`task:{id}` 缓存 status/progress（可选降级，未配置不阻塞）

## 前端设计

- **WorkspaceView.vue**：左侧 62% 对话区 + 右侧 38% 任务/数据面板，顶部工具栏（新建任务/导出）
- **对话区**：用户气泡；助手消息推理可折叠（默认收起）；工具卡片 tool_start 插入、tool_result 更新为 completed 显示完整结果（不截断），新卡片默认自动展开；中断卡片唤起 InterruptDialog
- **任务面板**：任务列表 + 状态徽标 + 进度条 + 实时日志
- **数据预览**：items_batch 增量追加行，列由首条字段动态生成，导出按钮
- **SSE 客户端**：fetch POST + ReadableStream 逐行解析（EventSource 不支持 POST body），useTaskRun 统一事件分发

## 验证方案

**启动**：
1. `docker compose up -d`（需本地 Docker；若无 Docker，提示用户自行安装 PostgreSQL/Redis 或改用 SQLite 起步）
2. 后端：`pip install -r requirements.txt && playwright install chromium`，`uvicorn app.main:app --reload --port 8000`
3. 前端：`npm install && npm run dev`

**端到端验证**（真实站点，如 ithome.com 新闻首页或 news.ycombinator.com）：
1. 新建任务输入 URL + 指令"抓取前 3 页的文章标题、链接、发布时间"
2. 观察 SSE 流式显示各节点推理与工具卡片、自动翻 3 页、验证、入库
3. 右侧面板状态流转 running→success、进度递增、数据表格逐页追加
4. 导出 CSV/JSON/xlsx 校验完整
5. 重启后端后历史任务与结果仍在（PostgreSQL 持久化验证）

**人工介入验证**：配置 `FORCE_INTERRUPT_AT=page_load` 模拟登录墙 → 任务停 waiting_interrupt → 弹窗输入"已手动登录，继续" → resume 从 page_load 继续跑完。

**断点续跑验证**：跑一半 kill 进程 → 重启 → 从 checkpoint 恢复继续而非重头开始。
